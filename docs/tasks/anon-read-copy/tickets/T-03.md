# T-03: the text summary and the JSON report

Status: open
Risk: medium (what a person and a script read; escaping of untrusted values)

Build `report.py` and the published `report.schema.json` (with its version, as `docs/spec/reports.md`
says) from T-02's result object.

Scenarios, each shown by a test on a real copy:

- S-3: one line per table and operation (table with schema, verdict, basis), the exposed table's
  evidence row, the exit code and what it means; summary on stdout, progress and stop on stderr.
- S-1 (reports): *Read the JSON report from a script* (valid against the schema, names its version,
  same facts as the summary: verdicts, bases, evidence, exit code, exact versions, exposed schemas,
  tables not reachable), *A stopped run still reports what it found* (both forms), *A row value
  cannot take over the terminal* (no escape byte in the summary; the JSON value equals the stored
  one).
- S-7's last clause: both reports name the exact versions the copy ran.
- *Two runs on the same migrations give the same report*: the two JSON reports are equal apart from
  the time of the run.

Check: the test command passes with every test above seen to fail first. Today there is no JSON
report or schema, so every check fails.
