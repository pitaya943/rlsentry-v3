# T-06: an interrupted run exits 2, as the spec says

Status: open
Risk: medium (a fix ticket for the pull request into main: one exit code on the interrupt path of
T-01's lifecycle; the copy's destruction itself does not change)

The verdict on #34 at `8ba0ade` (https://github.com/pitaya943/rlsentry-v3/pull/34#issuecomment-7217048365)
found that an interrupted run (SIGINT or SIGTERM) exits `130`, while `docs/spec/verdicts.md` (Exit
codes: `2` "could not finish (interrupted, or the copy failed)") and the exit-codes term in
`docs/spec/index.md` say `2`. The spec is the owner's merged rule; follow it.

- An interrupted run, by SIGINT or SIGTERM, at any point (build, seeding, attack), destroys the copy
  as it does now and then exits `2`, its message still saying it was interrupted.
- Fix the whole class: every place that states or asserts the interrupt's exit code agrees with
  the spec: the code, the tests (`tests/test_lifecycle.py` and any other), `README.md`,
  `.claude/skills/try-rlsentry/SKILL.md`, and `docs/spec/` if any line there says otherwise.
- The trail row of T-01 (08:38Z) said "SIGTERM 143-style"; add a trail row correcting it.

Check: with the code as it is, a test that sends SIGINT and one that sends SIGTERM while a run is
attacking and expects exit `2` and nothing left both fail (they get `130`); after the change they
pass, and `grep -rn 130 src tests README.md .claude/skills docs/spec` finds no exit code of 130.
