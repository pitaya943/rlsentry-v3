# T-04: the lab

Status: open
Risk: medium (what a learner is told to expect; the lab statements are what the tests check)

Bundle lab schemas as package data (`src/rlsentry/lab/<name>/migrations/*.sql` and a statement
file), each named for its flaw in the user's words, and `rlsentry lab` (list) and a way to run one by
name; record the command shape in the trail. Write `README.md` (what rlsentry is in two lines, how
to install it, how to run the tests, the lab). Then create the project's `try-rlsentry` skill with
`sc-try-it`.

Scenarios:

- S-8 in full: the list names each schema and its flaw in one line, builds nothing; each schema's
  verdicts, exit code and any stop equal its statement; between them, a read exposed for each reason
  (RLS off, a policy admitting everyone, a policy admitting some rows, a grant on some columns, a
  request without a key), and at least one schema showing a stop this task builds. No schema whose
  statement expects a protected read.
- S-5 *Migrations written for Supabase build* is shown on a lab schema written that way (reaches the
  attack); S-6 can use one too.

Check: a test runs every bundled schema and compares it with its statement, and a test collects the
answers and checks each listed reason appears; both seen to fail first. Today there is no lab.
