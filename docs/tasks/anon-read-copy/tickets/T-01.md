# T-01: the package, the copy, and the safety boundary

Status: open
Risk: high (the brief's first critical area: the copy is destroyed however a run ends, migration
code cannot reach the machine, nothing is sent anywhere but the copy, `--target` is refused)

Build, as [design.md](../design.md) shapes it: `pyproject.toml` (Python 3.10+, `pip install` from
the repository, console script `rlsentry`), `src/rlsentry/` with `cli.py`, `inputs.py`,
`versions.py`, `copy.py`, `supabase_setup.sql`, and `tests/` with pytest. A run in this ticket goes
as far as: inputs, versions, build the copy, apply migrations, the settings check, start PostgREST,
then (until T-02) report the tables of the exposed schemas it found and destroy the copy.

Scenarios, each shown by a test on a real copy (S-10: no stand-in except S-7's version script):

- S-7 in full: the series rule, the message naming program, version found, series needed; the
  server's version confirmed; both versions kept for the reports.
- S-5: *The copy is gone when a run ends* (finished, stopped with `2`, Ctrl-C while running),
  *A copy left by a killed run is removed by the next*, *A migration cannot reach the machine*
  (program, file read, file write, extension outside the list), *A setting a migration makes for
  the REST layer stops the run*, *A setting a migration puts on the anonymous role stops the run*
  (and the brief's Assumptions: `anon`, `authenticated`, `authenticator`, any `pgrst.*`; other
  settings on `postgres` do not stop), *Migrations written for Supabase build* (as far as the copy
  builds; the attack is T-02's), and *A live target is refused* (an address the test watches gets
  nothing, no name lookup).
- S-1 (attacking): *Run rlsentry on a plain folder of SQL files* ordering (the later file's effect
  is visible in the direct view; its read verdict is T-02's), *A migration that fails stops the
  run*; the #23 inputs: no `.sql` file, names equal but for case, `supabase/migrations/` used and
  said.
- S-10's harness: the suite fails (not skips) naming what is missing on a machine without
  PostgreSQL or PostgREST; set `test_command` in `.shilaycow/config.yml` to the command that runs
  it.

Check: `pip install -e . && <test_command>` passes, and each test above was seen to fail first. Today
nothing here exists, so every check fails.
